# ADR 008 — CDN & Edge Caching

**Status:** Accepted
**Date:** 2026-02-27
**Deciders:** Jubilee Engineering

---

## Context

Published content and binary assets must be edge-cached for global performance. The system
also requires cache invalidation when content is published, updated, or archived.

## Decision

**Cloudflare** as the CDN and edge caching layer.

## Rationale

- **Already in use:** `CF_ZONEID_API`, `CF_NAMESERVER01`, and `CF_NAMESERVER02` are
  configured in `.env`. Cloudflare is the active DNS and proxy provider for jubileeverse.com.
- **Cache purge API:** Cloudflare's `/zones/{zone_id}/purge_cache` endpoint enables targeted
  invalidation per URL. The existing `cache-flush` endpoint (`POST /api/admin/cache-flush`)
  already calls this. The PubOS publish pipeline will extend this pattern.
- **Workers (future):** Cloudflare Workers can serve A/B tests, personalization headers,
  and geo-targeted content at the edge without origin load — a natural Phase 4+ capability.
- **CloudFront consideration:** AWS CloudFront would pair well with S3 (ADR 004) but
  requires an AWS account setup and introduces vendor coupling between storage and CDN.
  Deferred until S3 migration (Phase 3).

## Cache Strategy

| Content Type | Cache TTL | Invalidation Trigger |
|-------------|-----------|----------------------|
| Published articles | 1 hour | On article publish/update/archive |
| Portal layout | 24 hours | On midnight PST reset |
| Images/assets | 30 days | On asset replace |
| API responses (`/api/*`) | No cache | Always origin |

## Cache-Control Headers

Express must set appropriate `Cache-Control` headers:
- Published HTML pages: `public, max-age=3600, s-maxage=3600`
- Images: `public, max-age=2592000, immutable`
- API endpoints: `no-store`

## Consequences

**Positive:**
- Zero additional cost — Cloudflare free tier covers JubileeVerse traffic volumes.
- Cache purge is already wired; extending it to PubOS publish events is low effort.
- DDoS protection and SSL termination are provided by Cloudflare automatically.

**Negative:**
- Cloudflare's cache rules must be configured via dashboard or Terraform (not in code).
  Document configuration in `docs/ops/cloudflare-cache-rules.md` (Phase 2).
- Cache stale periods mean updates may not be immediately visible to all users.
  Implement cache purge in the publish pipeline to mitigate.
